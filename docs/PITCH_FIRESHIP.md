## Our Architecture: The [∅] Framework

**Three principles:**
1. **Clarity** — every rule is a *structural law*, not a guideline
2. **Minimalism** — remove everything that doesn't add coherence
3. **Recursion** — same pattern works at every scale (from tokens to strategy)

**The core insight:**
Contradictions (A ⊕ B) don't need resolution. They need a *third thing* between them (I).

```
Problem:  "I want X AND I'm afraid of X"
Wrong approach: Solve one, compromise the other
Right approach: Find what's between want & fear
Result: Real path forward (the third thing)
```

This pattern applies to:
- Prompt engineering (conflicting requirements → find the synthesis)
- System design (competing priorities → find the mediation)
- Code architecture (different layers → find the interface)

**Why it saves tokens:**
- No circular reasoning (contradictions collapse immediately)
- No hedging language ("maybe", "could", "might")
- No context bloat (each piece of info serves exact purpose)
